# CAA 接口生产开发与验收规范

适用：`catia-v5-mcp-server` 的 CAA 开发与交付。生产目标遵循仓库 maintainer skill。
当前 Point 原生实现已在原 Clean 包通过 B30 验收；本仓库接入仍为实验性 Draft。
本规范中的生产要求不表示当前 Draft 已全部实现，差距见 [接入说明](caa-point.md)。

## 1. 范围和架构

```text
MCP schema/工具 → Python typed adapter → 串行 STA / RunOnce JSON → CATIA 主线程 CAA
```

- 一个接口完成一个业务动作；能用既有能力稳定完成就复用，采用 CAA 说明用途。
- CAA 负责模型操作，Bridge 负责通信，Python 负责验证/错误，MCP 负责协议。
- 只接入所需方法，不复制第二套 server、连接类、通信协议或宿主治理目录。
- Python 协议/schema 随包安装；原生 runtime 使用配置的绝对路径，不写死开发者目录。
- 声明 Windows/Python/CATIA/工具链与许可范围。调用前核对实例、源码契约、实际 DLL 路径与哈希；缺失或不匹配时拒绝调用。
- DLL 由 CATIA 加载，Python 不直接加载 CAA DLL；官方 SDK 由本机安装提供。

## 2. 接入和线程

- `catia_mcp/caa_client.py` 封装 preflight 和结果；`catia_mcp/tools/caa.py` 遵循 `get_tool_definitions()/execute()` 和 `catia_*` 命名。
- server 仅注册、调度、适配结果；业务算法放在对应模块。
- 把共享连接核验过的 CATIA 对象注入 client；CAA 只附着到指定的匹配实例，不自动启动普通 CATIA 或另选实例。
- COM 初始化、访问、释放在同一串行 STA 线程完成；CAA 在 CATIA 主线程运行，独立调用不得并发控制同一实例。
- 生产目标使用服务器管理的对象句柄及有效性代次；不得按同名对象静默重绑定。当前 Point Draft 的 PID/路径/名称定位是已声明的限制。

## 3. 契约与结果

- 输入写清对象类型、唯一定位、必填/默认、枚举、范围、单位、坐标系和副作用；schema 与执行行为一致。
- 禁止额外字段；执行层继续核验有限值、路径、实例、文档和目标状态。不存在、不唯一或不支持时明确拒绝。
- 结果使用 `ok/code/operation_id/tool/message/data/effects/diagnostics/warnings/recovery`；`ok` 是唯一成功判据。
- MCP 业务失败设置 `isError=true`，JSON 文本与结构化结果一致；保留最具体原生错误、失败阶段和部分修改证据。
- `effects.modified=null` 表示未知；不以缺失数据或零值冒充成功。声明回滚、重试及下一安全动作。
- 操作 ID 关联请求、响应和日志；日志不记录秘密、完整确认令牌或原始参数。
- Update 成功与预期效果分别核验；点接口回读坐标、参数驱动、名称和集合归属。

## 4. 写入、超时和恢复

- 写接口默认只读预览、未确认；执行须匹配完整计划/目标/状态及有效的一次性令牌。
- 状态变化或对象身份失效时在首次修改前拒绝旧预览；不得用同名同类型替换对象继续执行。
- 实例、文档、目标对象核验失败立即停止；不自动保存、覆盖、删除或关闭文档。
- 请求入口互斥且校验请求/响应 ID；前一请求未结束或状态未知时拒绝新操作。
- 超时、取消或断连不证明 CATIA 停止。送达或状态未知的写请求不得自动重试；保全请求/响应、阶段及已有修改。
- 生产恢复使用可验证的操作记录，按逆序恢复并回读；不把部分清理称为事务回滚。当前 Draft 仅支持人工检查恢复，没有自动回滚或弹窗治理。

## 5. 构建与交付

- 新增原生方法核实目标版本官方 API，检查 HRESULT/指针并正确释放引用；不跨请求缓存失效风险不明的模型指针。
- 不修改官方安装、头文件或生成头文件；Update/API/回读失败明确报错。
- Git/PR 提交点源码、必要资源、协议、适配、脚本、测试和文档；不提交 DLL、CATPart、官方 SDK、本机配置或生成产物。
- 构建说明给出工具链、配置变量、命令、退出码、输出位置和验证步骤。构建日志及 runtime manifest 留在本机。
- 记录构建的源码目录、分支、完整 HEAD、dirty、命令/配置和产物哈希；生产发布必须来自单一、已提交、可追踪状态。
- Point 原生旧验收摘要见 [原生证据](../caa/point_bridge/validation/native-evidence.json)：23 个 live gates 通过，原生源码哈希保留；新接入行为另验，不强制重复编译未变的原生源码。

## 6. 验收与发布

| 阶段 | 必须提供的证据 |
| --- | --- |
| 离线 | schema/路由、结构化结果、未知/部分写入、STA 串行、协议关联及失败用例通过 |
| 独立调用 | 目标环境使用同一调用模块完成预览/执行/原生回读 |
| MCP | 新服务进程完成发现、预览、确认、错误透传、模型回读和连接/线程验证 |
| 边界 | 缺确认、错实例/文档/目标、状态变化、过期/重放拒绝；超时不重试；失败保全可核验 |
| 发布 | 已提交源码、构建记录与实际加载产物一致；支持版本及许可证环境验证完成 |

- 分别报告旧原生验收、新接入验收和正式发布状态；未测试或失败不得称验收通过。
- 使用可丢弃模型；复用证据注明来源。已知限制：同名同类型替换不能检测、Update 故障未注入、B30 外未验证。
- Draft 可以提前评审，但须明示对象句柄、模型代次、恢复、弹窗及实机验证差距，不能宣称生产就绪。
- 修改、commit、push、合并、部署分别授权；开工 fetch 并记录基线，同任务继续原 worktree，保全他人修改。

本次范围仅 `catia_caa_demo_create_point` 及必需桥接，贡献者授权这部分按 MIT 公开。
其他私有 CAA 业务不纳入。最小需求记录：业务/契约、环境/来源、影响范围、验收证据、限制、授权。
